# Разметчик видео

Встроенный режим: `./run.sh ui`, вход на основной сайт, вкладка «Разметка».
Самостоятельный режим: `./run.sh annotate`, http://127.0.0.1:18862.
В обоих случаях запускайте команды из корня проекта. GPU для ручной работы
не нужен. Встроенный режим — общее рабочее место авторизованной команды.

## Вход и сохранение

`ANNOTATION_DATASET` указывает на набор с каталогом `open/videos/`.
Без дополнительных JSON редактор использует имена видео. Необязательные файлы:

- `reference/source_labels.json`: список объектов `{"filename":"sample.mp4"}`;
  дополнительные `label` и `timecode_sec` показываются как исходная разметка.
- `reference/labels_final.json` и `audit/labels_annotated.json`: список записей
  с `filename`, `observed_action`, `timecode_sec`, `limitations` для AI-подсказок.
- `reference/manual_review.csv`: прежние заметки, связываемые через `group_id`.

`ANNOTATION_RUNTIME` хранит `annotations.sqlite3`, историю правок, отдельные
AI-предложения, MP4-кеш и извлечённые кадры. Не публикуйте этот каталог.
Для резервного копирования работающей базы используйте SQLite backup API,
учитывающий WAL. Имена файлов определяют ID видео: переименование меняет ID.

## Порядок работы

1. Просмотрите видео, добавьте условных участников и эпизоды: кто, что, кому,
   с каким предметом и в каком интервале. Не записывайте реальные имена.
2. Во вкладке фигур клавиша R создаёт рамку, Z — полигон, V — выбор.
   Для движущегося объекта добавляйте ключевые кадры; координаты нормализованы.
3. Подтверждайте зоны, видимость и границы интервалов. Открытая дверца сама
   по себе не доказывает нарушение, а отсутствие детекции не доказывает отсутствие.
4. Укажите проверяющего, вывод и просмотр целиком, затем отметьте «Проверено».

Правки сохраняются автоматически с проверкой версии. Конфликт двух окон
возвращает 409; скачайте черновик и перенесите изменения вручную.
Перенос эпизодов и зон между видео требует повторной проверки.

Экспорт в самостоятельном режиме: `/api/export`, `/api/export/episodes`,
`/api/export/coco`; во встроенном режиме добавьте префикс `/annotate`.
COCO содержит явные ключевые кадры проверенных аннотаций, ссылки на кадры,
рамки и принятые маски. Это не гарантия исчерпывающей разметки каждого кадра.
Непринятые AI-черновики в обучающий экспорт не включаются. Делите выборки по
сценам и группам дубликатов до аугментаций.

## Дополнительные AI-инструменты

Ручной редактор не вызывает модели. `preannotation/` содержит отдельные
исследовательские CLI: локальные детекции, VLM-предложения, SAM2-контуры,
проверку геометрии и отчёты о покрытии. Для них нужны GPU-профиль зависимостей
и соответствующие локальные веса. Для SAM2 дополнительно установите официальный
пакет `sam2` и задайте `ANNOTATION_SAM_CHECKPOINT`. Для vLLM используется отдельное
совместимое окружение и `ANNOTATION_VLLM_BIN`; `serve_vlm.sh` слушает localhost.
Наличие сохранённого предложения не означает, что оно верно: его принимает человек.

Запускайте модули из корня проекта; передавайте те же `ANNOTATION_DATASET`,
`ANNOTATION_RUNTIME`, `KASSA_MODELS_DIR` и `KASSA_VLM_CHECKPOINT`, что и сервису.
Прямой `python -m ...` не читает `.env`, кроме описанного ниже Nace-клиента.
`python -m annotation_service.preannotation.batch --help` показывает параметры.
Полный GPU-конвейер в этой сборке не перепроверялся.

`nace_classify.py` — необязательная классификация **текста** через внешний Nace API.
Она запускается явно и читает `NACE_API_KEY` из окружения или `.env`.
Свободные заметки и описания передаются внешнему сервису; видео не отправляются.
Перед сетевым запуском проверьте разрешение на передачу этих текстов.

```bash
.venv/bin/python -m annotation_service.nace_classify --dry-run \
  --labels data/dataset/reference/labels_final.json \
  --database backend/runtime/annotations/annotations.sqlite3 \
  --output data/nace-preview
```

Команда лишь сохраняет точные входы без запросов к API. Удаление `--dry-run`
включает сетевую классификацию и возможную тарификацию провайдера.
Результаты не импортируются в ручную разметку автоматически.
