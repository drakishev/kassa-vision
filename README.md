# Kassa Vision

Локальный инструмент для анализа и ручной разметки видео кассовых операций.
Сайт объединяет загрузку видео, историю анализов, просмотр кадров и разметчик.
Разметчик также работает самостоятельно, без основного сайта и GPU.

В репозитории только код, синтетические тесты, публичные нормативные источники
и уведомления о лицензиях. Исходных записей, разметки, результатов прежних
экспериментов, учётных записей и весов моделей здесь нет.

## Быстрый старт без GPU

Нужны Linux, Python 3.11, Node.js 22.12+ с npm, `ffmpeg` и `ffprobe`.
Из корня репозитория:

```bash
./setup.sh --cpu
./run.sh demo
./run.sh ui
```

Откройте **http://127.0.0.1:18863**. При первом запуске создаётся локальная
учётная запись: логин и пароль находятся в
`backend/runtime/ui/admin-credentials.json`. После входа выберите **Разметка**
или откройте `/annotate/`. Demo создаёт шестисекундную тестовую таблицу,
а не запись людей и не пример работы модели.

В CPU-режиме доступны сайт, ручная разметка и экспорт. Автоматический анализ
требует отдельного GPU-процесса; до его запуска сайт показывает, что анализатор
не готов. Остановка — `Ctrl+C` в терминале.

## Только разметчик

```bash
./run.sh demo
./run.sh annotate
```

Адрес: **http://127.0.0.1:18862**. Для минимальной установки без Node.js:

```bash
python3.11 -m venv .venv
.venv/bin/python -m pip install -r annotation_service/requirements.txt
./run.sh annotate
```

Самостоятельный разметчик слушает только localhost и не имеет отдельного
входа. Встроенный разметчик защищён сессией основного сайта. Его набор видео
и аннотации общие для всех авторизованных участников этой установки; это
рабочее место доверенной команды, без разграничения наборов по пользователям.
История автоматических анализов по-прежнему изолирована по учётным записям.
Оба режима разметчика используют один `ANNOTATION_RUNTIME`.

## Свои видео

Положите разрешённые к обработке видео в `data/dataset/open/videos/`.
Поддерживаются `.mp4`, `.mov`, `.mkv`, `.avi`; для браузера нужен видеопоток,
совместимый с MP4 (обычно H.264). Сервис перепаковывает поток без перекодирования,
поэтому расширение файла само по себе не гарантирует воспроизведение.
Перезапустите разметчик или сайт после добавления файлов.

Файлы `reference/source_labels.json`, `reference/labels_final.json`,
`audit/labels_annotated.json` и `reference/manual_review.csv` необязательны.
Без них редактор перечисляет видео напрямую. Необходимые форматы и экспорт
описаны в [инструкции разметчика](annotation_service/README.md).

Локальные параметры задаются в `.env` по образцу `.env.example`.
Относительные пути разрешаются от корня проекта. `.env` — доверенный локальный
shell-файл, исполняемый `run.sh`; не используйте чужие конфигурации без проверки.
Видеофайлы, SQLite-базы, ключи и производные результаты остаются в игнорируемых
каталогах `data/` и `backend/runtime/`.

## Автоматический анализ на GPU

Это необязательная исследовательская часть. Текущая конфигурация рассчитана
на NVIDIA GPU с примерно 80 GiB свободной VRAM. Установите совместимый драйвер
и GPU-зависимости, затем загрузите публичные веса:

```bash
./setup.sh --gpu
./run.sh prepare
.venv/bin/hf download Qwen/Qwen3.8-27B \
  --revision 1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0 \
  --local-dir backend/models/vlm
./run.sh api
```

В другом терминале выполните `./run.sh ui`. Путь к весам и GPU можно изменить
через `KASSA_MODELS_DIR`, `KASSA_VLM_CHECKPOINT` и `KASSA_GPU` в `.env`.
Подготовка скачивает веса; обработка использует локальные модели.
`./run.sh smoke` проверяет работающий анализатор на искусственном ролике.

Конвейер: Grounding DINO → ByteTrack + RTMW → локальная VLM → проверка основного
события. Выводы требуют просмотра человеком. Синтетические тесты проверяют
программные контракты, а не качество распознавания. Новый GPU-прогон и чистая
установка GPU-профиля в рамках подготовки этой версии не выполнялись.

API доступен через тот же сайт: `POST /api/v1/analyze` и
`GET /api/v1/jobs/{job_id}`, заголовок `X-API-Key`. Локальный ключ создаётся в
`backend/runtime/api.key`; `KASSA_API_KEY` позволяет задать его самостоятельно.
API принимает `.mov` до 256 MiB и 180 секунд. Публичный туннель не создаётся.

## Структура и развитие

- `backend/` — API, очередь задач, учётные записи и локальные модели.
- `frontend/` — React/TypeScript-интерфейс и браузерные тесты.
- `annotation_service/` — разметка эпизодов, рамок, зон и масок; JSON/COCO-экспорт.
- `annotation_service/preannotation/` — необязательные локальные AI-черновики.
- `configs/nace_scenarios.json` — категории необязательной текстовой классификации.
- `scripts/` — искусственное demo и проверка файлов перед публикацией.
- `licenses/` — лицензии и происхождение сторонних компонентов.

## Проверки и публикация

```bash
./run.sh test
python3 scripts/check_publication.py
# Проверка содержимого индекса после git add:
python3 scripts/check_publication.py --staged
# Установленный отдельно Gitleaks:
python3 scripts/check_publication.py --gitleaks
```

`./run.sh test` выполняет Python-тесты на искусственных данных, frontend-тесты
и сборку. Подробности браузерных проверок — в [frontend/README.md](frontend/README.md).
Опциональный локальный pre-commit hook: `git config core.hooksPath .githooks`.
Он требует установленный `gitleaks` и отклоняет запрещённые файлы и секреты.

Начинайте публикацию с этой чистой Git-истории. Не подключайте старые bundle,
ветки, служебные снимки или архивы: удаление файла в новом коммите не удаляет
его из прежних коммитов. Перед публикацией проверьте выбранные Git-имя и email.

Собственный код распространяется по [MIT](LICENSE). У моделей, библиотек,
шрифтов и нормативных материалов свои условия; сохранены исходные уведомления.
Ограничения и неопределённость условий RTMW перечислены в [licenses/README.md](licenses/README.md).
